# FAQ-Layout — Team Summary

**FAQ-Layout** is an empirical study of an approximate **Quadratic Assignment Problem (QAP)
pre-placement** pass that pre-seeds the initial qubit layout for downstream quantum routers
(Qiskit SABRE, PyTKET LexiRoute). It wraps SciPy's `quadratic_assignment(method="faq")` with
**random multi-start** + Sinkhorn normalization and a discrete 2-opt polish (the shipped
default; the earlier structured-Gaussian multi-start is deprecated — see
`reports/a5_results.md`).

## Central results (see the README for the full tables)

The authoritative, reproducible dataset is generated by `benchmarks/benchmark_eval.py` over 20 tasks ×
20 paired seeds (`benchmarks/results/benchmark_eval_results.json` + `benchmarks/results/benchmark_eval_raw_seeds.json`). Key, honest
findings reported there (FAQ arms use the random multi-start default):

- **FAQ + PyTKET** reduces SWAPs vs PyTKET's own `GraphPlacement` on every synthetic-grid MQT
  task (e.g. VQE‑N50 −93.1%) and on several IBM tasks (e.g. Grover-N10 −10.6%, QAOA-N10/N20,
  QFT-N20, VQE-N50 −34.2%, Random 3-regular).
- **FAQ + SABRE rarely helps** — it usually increases SWAPs vs default SABRE, and only wins on
  three hand-crafted holdout rows (QRAM Brisbane, Ripple/QRAM synthetic grid). Pre-seeding can
  over-constrain SABRE.
- FAQ + PyTKET is **not** uniformly better on IBM (it hurts Grover‑N8/N12 and the QRAM/Ripple
  holdouts).
- Real FAQ overhead is ~2–29 s/circuit (single-threaded Python solve), so it is only worth it
  when the routed circuit is large or re-used many times.

The lower-SWAP claims above are *mean* differences; several are not statistically significant,
and the fidelity-loss proxy can disagree with SWAP count. See
[`reports/statistical_fidelity_analysis.md`](statistical_fidelity_analysis.md) for the paired
Wilcoxon and fidelity analyses (review points #2 and #5).

## Repository layout

| Path | Purpose |
|:---|:---|
| `qap_compiler/` | Modules A–E + pipeline + a Qiskit `FAQPlacementPass` |
| `benchmarks/benchmark_eval.py`, `benchmarks/benchmark_eval_parallel.py`, `benchmarks/benchmark_eval_strided.py` | Canonical K=20 benchmark (serial + CPU-parallel runners) |
| `benchmarks/benchmark_ablations.py` | QAP-cost ablation study |
| `benchmarks/analyze_significance.py` | Paired Wilcoxon + BH significance testing (analysis-only) |
| `benchmarks/render_tables.py` | Renders README Tables 1–2 from the results + significance JSON (incl. per-row † markers) |
| `benchmarks/benchmark_fidelity.py`, `benchmarks/report_fidelity.py` | Fidelity-loss proxy on routed circuits + delta table (currently describes the previous Gaussian-era canonical circuits) |
| `benchmarks/results/benchmark_eval_results.json`, `benchmarks/results/benchmark_eval_raw_seeds.json`, `benchmarks/results/benchmark_ablation_results.json` | Canonical committed results |
| `benchmarks/results/significance_results.json`, `benchmarks/results/benchmark_fidelity_results.json`, `benchmarks/results/benchmark_fidelity_comparison.json` | Significance + fidelity analysis outputs |
| `tests/` | Unit/integration tests |
| `reports/` | This summary, a walkthrough, data provenance, the validation review |
| `historical/` | Superseded earlier experiment rounds (archived for provenance) |

Python dependencies are managed with **uv** (`pyproject.toml` + `uv.lock`, Python 3.12).
